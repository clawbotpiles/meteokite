# Contributing Guide (Project-level)

## Branching

- Use short-lived feature branches.
- Keep pull requests focused and small.

## Code organization

- Respect Clean Architecture boundaries.
- Keep feature-first folder layout.
- Do not mix UI and infrastructure code.

## Pull request expectations

- Explain why, not only what.
- Include screenshots for UI changes.
- Mention accessibility checks for interactive screens.

## Quality checks

- `flutter analyze`
- `flutter test`

## Design system compliance

- Follow `design-system/meteokite/MASTER.md`.
- New screens must stay consistent with global tokens and accessibility constraints.
